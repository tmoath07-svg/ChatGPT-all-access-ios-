# INRPF 2.01

تطبيق iOS عربي لتحليل وتجهيز ملفات مودات GTA V محلياً على iPhone وiPad.

## الإصدار 2.01 ومحرك المعالجة المحلي (1.6.0)

- إضافة مكتبة Rust ثابتة مدمجة داخل تطبيق iOS عبر C ABI.
- قراءة وفحص ترويسة وجداول RPF المدعومة بواسطة rpf-archive.
- بناء أرشيف RPF7 عام غير مشفر من مجلد ملفات محلي.
- تحويل بنيوي لبعض موارد RSC7 من امتدادات Y* إلى O* مع الحفاظ على الترويسة وإعادة ضغط الحمولة.
- تحليل YTD واستخراج الخامات إلى ملفات DDS باستخدام rage-formats.
- فحص بنية الأرشيف الناتج مباشرة بعد البناء.
- لا يتم رفع ملفات المستخدم إلى خادم عند استخدام أدوات المحرك المحلي.
- حدود المرحلة الأولى: 20,000 ملف، عمق مجلد 64 مستوى، ومجموع بيانات 512MB لكل عملية.
- يتم تجاهل الروابط الرمزية لمنع الخروج من مجلد المصدر أو الدوران داخل المسارات.

## حدود تحويل PS4

استخراج YTD إلى DDS لا يساوي إنشاء OTD. وبناء حاوية RPF7 عامة لا يساوي تحويل موارد GTA V إلى صيغة PS4. ما زالت معالجة موارد RSC7/YFT/YTD الخاصة بالمنصة، وخطوات ragebuilder التي تعتمد على ملفات Windows التنفيذية ومكتباتها، قيد النقل والاختبار. لا تعتبر أي حزمة صالحة لجهاز PS4 حتى تنجح اختبارات بنية الموارد ثم اختبارها داخل اللعبة.

## طرق الاستيراد

- اختيار ملفات ZIP وRAR من تطبيق «الملفات».
- اختيار مجلد كامل من تطبيق «الملفات».
- تنزيل ملف ZIP أو RAR من رابط HTTP/HTTPS مباشر.

## تجهيز الملفات

- فك الأرشيف إلى مجلد عمل مستقل.
- الاحتفاظ بالملف الأصلي دون تعديله.
- منع مسارات الأرشيف غير الآمنة أثناء الفك.
- إنشاء dlclist.xml بصيغة Orbx المطلقة:
  `/data/orbx/gta/rpf/dlc_addon/NAME/`

## متطلبات البناء

- XcodeGen
- Swift Package: libarchive-for-swift 1.0.0 (SwiftArchive)
- Rust stable مع target `aarch64-apple-ios`
- iOS 16.0 أو أحدث
- Bundle ID: `com.tmoath07.gta-converter`

## التراخيص

يعتمد محرك RPF المحلي على مكتبة `rpf-archive` إصدار 0.10.0 المرخصة بـ Unlicense:
https://github.com/VIRUXE/rpf-archive-rs

راجع تراخيص SwiftArchive ومكتباتها قبل توزيع التطبيق.


## FTP في الإصدار 2.01

- تجربة EPSV أولاً ثم PASV للتوافق مع خوادم FTP القديمة.
- استخدام عنوان اتصال التحكم نفسه لاتصال البيانات عند PASV لتجنب عناوين الشبكة غير القابلة للوصول التي قد يعلنها خادم PS4.
- إنهاء تدفق رفع الملف بإشارة EOF قبل انتظار رد نجاح الخادم.
- الرجوع من MLSD إلى LIST فقط عندما يعلن الخادم أن MLSD غير مدعوم، مع إظهار أخطاء الشبكة الفعلية بدلاً من إخفائها.
- لم يتم اعتماد توافق FTP مع كل إصدارات GoldHEN إلا بعد اختبار اتصال فعلي على الجهاز.
